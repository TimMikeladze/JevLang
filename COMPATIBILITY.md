# Portable engine implementation evidence

The complete contract is [portable-platform.md](../jev-lang/docs/portable-platform.md),
and [HANDOFF.md](HANDOFF.md) is the working note: what is finished, what is next,
and which oracle pins down each piece.
This package is under active implementation. It is not yet a feature-complete
replacement for the Racket implementation or a finished SaaS.

Verified by differential test against the Racket oracle, on the policies above:
wire questions (including runtime options and families), built state with
redaction and caps, decisions, first/all/collect routes, on-read and eager
gates with their trace prose ("needed confidence >= 0.80; otherwise: ..."),
review bands, flags, typed actions, confirmation, schedules, clarifications,
`planFor` collapsing (no items is a hold, one item is that decision), family
readings, informational reads that log nothing, and score detail read from the
answer's own legend.

Not yet ported: running a stability check, which calls a provider n times. Its
statistics — the per-question mean, standard deviation, range, modal answer, flip
rate and the gates, band edges and named thresholds the observed noise crosses —
are ported and pinned against `question-stabilities`; collecting the repeats is
the caller's, and that part has no test.

Known language gaps: code lookup (`jev/code`, which needs an SGX executable);
remaining compile warnings (the errors in `examples/broken/` are all refused);
`include-questions`,
`#:options-file` and `#:options` (compile-time option sources, which the
portable builders express in host code); trace prose beyond reading detail;
signals in reference-policy differentials; replay pipelines; monitoring and
calibration. A policy with runtime questions cannot recompute the Racket
`questions_sha256` identity, so such fixtures are verified against the
questions they recorded instead. The current engine does not call providers or
execute handlers. Python launches a local engine process per operation;
performance and long-lived process support still need attention before a
production release. JavaScript cannot stop a running function, so a handler that
passes its timeout is abandoned rather than killed, and the error says it may
have acted. Handlers are host functions, so the Python SDK decides but does not
dispatch.
